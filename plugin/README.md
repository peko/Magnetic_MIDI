# wooting-analog-plugin-cidoo

A [Wooting Analog SDK](https://github.com/WootingKb/wooting-analog-sdk) plugin for the CIDOO C80
(`2e3c:c365..c368`). With it, any SDK client (games, `wooting-analog-midi`, etc.) can read per-key analog values from the C80.

- The plugin implements the SDK's **C plugin ABI** (`includes/plugin.h`). ABI 1 is the default and matches the released SDK 0.9.x. `--features abi2` builds for SDK main/0.10+.
- A background thread opens the vendor HID interface (usage page 0xFF1B) with hidapi and starts the
  trigger-test travel stream. On disconnect it reconnects every second and fires Connected/Disconnected events.
- Value per key = `travel / max_travel` (0.0–1.0). `max_travel` comes from the keyboard (340 = 3.40 mm).
  Keys are reported as HID usages (`src/keymap.rs`, generated by `tools/gen_keymap.py`). Fn and the unnamed slot 15 use custom codes `0x0200 + index`.
- The keyboard keeps typing normally while the stream is open.

## Build
```sh
cargo build --release              # SDK 0.9.x (ABI 1)
cargo build --release --features abi2   # SDK 0.10+ (ABI 2)
cargo test
```
Needs `libudev` (part of systemd) at runtime.

## Install (Linux)
```sh
sudo install -Dm755 target/release/libwooting_analog_plugin_cidoo.so \
  /usr/local/share/WootingAnalogPlugins/cidoo/libwooting_analog_plugin_cidoo.so
```
The SDK itself (`libwooting_analog_sdk.so`) comes from the
[releases](https://github.com/WootingKb/wooting-analog-sdk/releases) page or the `.deb`/AUR package.

## Test without installing
SDK 0.9.1 only looks in `/usr/local/share/WootingAnalogPlugins`. You can test without root by bind-mounting
a directory over that path inside an unprivileged user+mount namespace:
```sh
mkdir -p /tmp/plug/WootingAnalogPlugins/cidoo && cp target/release/*.so /tmp/plug/WootingAnalogPlugins/cidoo/
unshare -rm sh -c 'mount --bind /tmp/plug /usr/local/share && \
  RUST_LOG=info CIDOO_PLUGIN_LOG=info python3 ../tools/sdk_harness.py /path/to/libwooting_analog_sdk.so 30'
```
Tested on 2026-11-14 with SDK v0.9.1: the plugin loaded as a C plugin with ABI 1, the C80 was listed
(`CIDOO / CIDOO C80`, pid c368), and over 30 s about 28k `read_full_buffer` polls returned smooth 0–1 values for 26 different keys.

## Limitations
- Values are updated only when the keyboard reports a change. If a packet is lost, a key can stay at its last value until it moves again.
- `device_id` is a hash of vid/pid/name, because the C80 has no serial number. Two identical C80s would get the same ID.
- Only one CIDOO keyboard at a time is supported.
- Do not run it while the official web driver is open: both use the same test mode.
